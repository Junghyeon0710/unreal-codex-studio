# 문 구현·독립 검토 데모

[English](../door-demo.md) · 한국어

[검증 JSON](../evidence/door-demo.json)

과거 로컬 테스트 결과를 기록한 문서입니다. 문 소스 프로젝트·생성 에셋·실행 패키지·
원본 로그·스크린샷·영상은 로컬에만 보관하며 배포하지 않습니다. 로컬 60초 영상에는
고정 30fps 엔진 프레임을 사용했으며 성능 측정 자료는 아닙니다.

## 실제로 나눈 작업

| 실제 하위 에이전트 | 수행한 작업 |
|---|---|
| `/root/door_implementer` | C++ 문, 장면, 테스트 캐릭터, HUD와 동작 검사 구현 |
| `/root/door_reviewer` | 소스 독립 검토 및 빌드·PIE·패키지·캡처 원본 증거 검토 |
| `/root/workflow_implementer` | 협업 지침·기록 도구 구현 및 검토 지적 수정 |

총괄 담당은 요구사항과 파일 소유 범위를 정하고 에디터/MCP 작업을 단독으로 수행했습니다.
문 소스에서는 첫 검토에 수정이 필요한 문제가 발견되지 않았습니다. 수정 장면을
만들려고 결함을 심지 않았습니다.

협업 도구 검토에서는 실제 결함 **W1**이 발견됐습니다. 구현본 제출 후 검토 전에
소스가 바뀌면 검토와 재제출이 모두 막혔습니다. 원래 구현 담당자가 이전 기록을
보존하는 명시적 재제출 경로를 추가했고, 독립 검토 담당이 재시험 후 승인했습니다.
[검토·수정 기록](../evidence/feature-loop.json)에 두 차례 제출과 지적 사항을 남겼습니다.

실제 호스트의 별도 하위 에이전트를 사용했지만, TOML 역할 9개를 모두 실행했다는
뜻은 아닙니다. 기록 도구가 에이전트 식별자의 진위를 인증하는 것도 아닙니다.
[재사용 가능한 협업 절차](../feature-loop.md)를 참고하세요.

## 검증 결과 — 2026-11-06

Windows / Unreal Engine 5.8.4 / Win64 Development / D3D12의 별도 샘플에서 확인했습니다.
사용자의 기존 게임은 수정하지 않았습니다.

| 단계 | 실제 결과 |
|---|---|
| Python 도구 | 28개 테스트 통과, 이 중 협업 기록 도구 테스트 12개 |
| 설정 | 스킬 15개·역할 정의 9개 검증 통과 |
| C++ 에디터 빌드 | 성공, 12개 작업, 전체 호출 시간 104.72초 |
| 공식 MCP | 프로젝트 확인, 문 Blueprint 파생 클래스 생성·컴파일·저장·재확인, PIE 시작·종료 |
| PIE 문 동작 | 12개 검사 모두 통과 |
| UAT 패키징 | 성공, 전체 호출 시간 206.77초 |
| 패키지 일반 실행 | 12개 검사 통과, 종료 코드 0, 오류 로그 0개, NVIDIA TSR 드라이버 경고 1개 |
| 영상 캡처 | 12개 검사 통과, 종료 코드 0, 실제 엔진 프레임 557개 |
| 완료 판정 | 문 1차 제출, 협업 도구 2차 제출 모두 통과 |

일반 시나리오는 게임 시간 18.50초이며 시작부터 프로세스 종료까지는 75.03초였습니다.
캡처 전체 실행은 68.62초였습니다. 성능 보장 수치가 아니라 이번 실행에서 관측한 시간입니다.
검토 담당이 원본 로그, 결과 JSON, 소스 해시, 실행 식별자와 동작 프레임을 별도로
확인했습니다. [최종 검토 기록](../evidence/door-runtime-review.json)에 범위를 명시했습니다.

실제 Pawn을 충돌 영역으로 이동시키고 문 경첩의 실제 회전값을 검사합니다.
처음 닫힘, 일반 오브젝트 무시, 접근 시 열림, 한 캐릭터의 여러 충돌 컴포넌트,
여러 캐릭터, 마지막 캐릭터 파괴, 닫히던 중 재접근과 자연스러운 방향 전환,
완전 재열림과 최종 닫힘을 확인했습니다. 사람이 키보드로 조작한 테스트는 아닙니다.

## 재현과 한계

문 테스트 샘플은 로컬 전용이므로 이 보고서에 재현용 프로젝트를 포함하지 않습니다.
일반 실행은 새 실행 식별자, 결과 JSON, 스크린샷, 각 검사 결과, 종료 코드와 로그를
함께 확인해야 합니다. 컴파일이나 종료 코드만으로 성공을 판정하지 않습니다.

캡처는 `-DoorCapture -DumpMovie -usefixedtimestep -fps=30`과 임시 프레임 저장 경로를
사용합니다. 캡처 모드는 번호가 붙은 프레임 파일을 만들므로 단일 스크린샷 파일명
검사만 생략합니다. 별도의 일반 실행에서는 해당 스크린샷도 확인했습니다.

MCP의 Blueprint 검사와 게임 모드가 생성한 네이티브 C++ 문의 동작 검사는 구분됩니다.
에디터가 런타임 복사본에 자동 생성한 Android File Server 설정은 배포 소스와 공개
증거에서 제외했습니다. 런타임 INI 전체가 배포 소스와 바이트 단위로 같다고 주장하지
않습니다. 실행 파일 해시는 최상위 런처만을 대상으로 합니다.

멀티플레이, Shipping, 수동 키보드·게임패드, 저장·불러오기, 장시간 플레이,
다른 엔진 버전과 전체 Unreal Automation은 검증하지 않았습니다.
영상·스크린샷·직접 작성한 문 C++ 프로젝트는 로컬에만 보관합니다. Epic 엔진·
플러그인 소스, 생성된 에셋 바이너리와 게임 패키지 바이너리도 배포하지 않습니다.


현재 Astra/Sol 5개 전문 담당의 배치 Blueprint 검증은 [새 실행 보고서](studio-door-validation.md)에 기록했습니다. 로컬에 보관한 기존 영상은 이전 실행이며 새 실행을 보여주지 않습니다.
