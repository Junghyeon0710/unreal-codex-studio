# Astra 스튜디오: 배치된 Blueprint 문 검증

> 과거 5인 통합 실험 기록입니다. 아래 결과는 가변 팀 구성 수정 전의 명시된 고정 스냅샷에만 해당합니다. 당시 테스트 35개·게이트가 현재 변경 소스를 검증하지는 않습니다. 현재는 [가변 팀 구성](../feature-loop.md) 정책이며 모든 작업에 5명을 요구하지 않습니다.

실행일: 2026-11-06. **완료: 독립 검토·에디터 작업·기술 검증·게임플레이 QA를 통과했고 최신 2회차 게이트가 종료 코드 0을 반환했습니다.** 소스 승인과 C++ 재빌드 성공만으로 5개 전문 단계가
완료됐다고 판단하지 않습니다.

## 실제 세션과 모델 귀속

기존 루트 대화의 모델을 소급해서 바꾼 것이 아닙니다. 별도 총괄 세션
`/root/astra_director`를 `gpt-6-astra`로 명시해 실행했고, 이 총괄이 실제 호스트
호출로 서로 다른 `gpt-6.1-sol` 전문 세션 5개에 작업을 위임했습니다.

| 담당 | 실제 호스트 세션 ID | 명시한 모델 |
|---|---|---|
| 총괄 | `/root/astra_director` | `gpt-6-astra` |
| 코드 구현·수정 | `/root/astra_director/sol_code` | `gpt-6.1-sol` |
| 독립 소스 검토 | `/root/astra_director/sol_review` | `gpt-6.1-sol` |
| 단독 에디터·에셋 작업 | `/root/astra_director/sol_editor` | `gpt-6.1-sol` |
| 기술 검증 | `/root/astra_director/sol_verification` | `gpt-6.1-sol` |
| 독립 게임플레이 QA | `/root/astra_director/sol_qa` | `gpt-6.1-sol` |

호스트의 동시 실행 한도에 맞춰 순차·교대 실행했습니다. 여섯 세션을 모두 동시에
실행해야 하는 것은 아닙니다. 총괄은 누락된 전문 단계를 조용히 대신하지 않고
인계와 결과 수집을 담당합니다. ID·모델 필드는 실행 귀속 기록이며 암호학적인
신원 인증은 아닙니다. TOML 역할 파일 설치만으로 실제 실행이 증명되지는 않습니다.

## 기존 샘플에서 바꾼 부분

이번 작업은 Git에서 제외한 로컬 전용 `examples/door-demo`를 확장했습니다. 새 게임을 처음부터
제작했다고 주장하지 않습니다. 게임 모드는 레벨에 배치된 `AStudioDoorActor`를
하나 선택하며 Blueprint 자식 클래스도 포함합니다. 여러 개면 명확히 실패하고,
없으면 기존 네이티브 생성 경로를 사용합니다. 자동 이동 Pawn은 로컬 X축 양의
방향에서 접근한 뒤 실제 반대쪽인 음의 방향에서 접근·재진입합니다. 무대 메시,
Pawn 경로와 카메라는 선택한 문의 Transform을 따릅니다.

새 보고서 필드 `map_package`, `door_selection`, `door_class`, `door_actor_path`,
`door_origin`, `door_is_blueprint`로 실제 맵과 선택된 인스턴스를 식별합니다.
에디터 담당이 `/Script/StudioDoor.StudioDoorActor`를 상속한
`/Game/StudioDoor/BP_StudioDoor`를 컴파일·저장하고
`/Game/StudioDoor/StudioDoorValidation` 맵을 저장했으며 배치된 문이 하나임을 확인했습니다.
PIE는 `/Game/StudioDoor/BP_StudioDoor.BP_StudioDoor_C`를 선택했고
`door_selection: level_placed`, `door_is_blueprint: true`, 맵 패키지
`/Game/StudioDoor/UEDPIE_0_StudioDoorValidation`을 기록했습니다.
네이티브 대체 경로의 성공으로 이 결과를 대신하지 않았습니다.

## 독립 검토에서 발견한 문제와 동일 작성자의 수정

독립 검토자는 실제 메시 크기 회귀 **R1 / P2**를 발견했습니다. `AddBox`가 지정한
메시 크기를 적용한 뒤 Actor Transform을 설정하면서 루트 크기를 덮어써 바닥·벽 등
서로 다른 크기의 물체가 기본 크기 큐브가 되는 문제였습니다. 총괄은 R1을 원래
구현 세션에 전달했습니다. 같은 작성자가 최종 Transform에서
`Scale * DoorTransform.GetScale3D()`를 적용하고 덮어써지던 크기 설정을 제거했습니다.

검토자가 수정 스냅샷을 다시 독립적으로 확인하고 R1을 종료한 뒤 승인했습니다.
두 제출 사이 변경 파일은 `StudioDoorMode.cpp` 하나입니다. 수정 과정을 보여주기
위해 결함을 의도적으로 넣지 않았습니다.

| 소스 회차 | Digest | 독립 검토 결과 |
|---|---|---|
| 최초 | `0e3fd7137183bdc2e758da0dd9c1a13f9cf7cb3adc228ee333f13941f45feffd` | R1 수정 요청 |
| 수정 | `fc2de0a948b9cf3731201cbee7c7d5d11ade005d6f6c0988c3bf8f8ae2a51189` | 승인·R1 종료 |

## 기술 검증

Sol 검증 담당이 수정된 에디터 타깃을 재빌드했고 종료 코드 0, 101.22초였습니다.
저장소 테스트 35개와 스킬 15개·역할 13개 검증을 통과했습니다. Win64 Development
BuildCookRun은 123.97초, 종료 코드 0으로 완료했습니다. Zen 스테이징 준비 재시도가
자동 복구된 사실도 기록했습니다.

새 패키지 실행 `6416d533d5024c0080d436640019545b`는 실제 페이로드 실행 파일을
직접 시작해 검사 12/12개를 통과했습니다. 게임 시간 18.50초·실제 시간 72.81초였고,
저장한 맵과 배치 BP를 선택해 D3D12로 스크린샷을 기록했습니다. 마지막 상태는
닫힘·점유 0개, 종료 코드 0이며 Error/Fatal/Ensure 로그가 검출되지 않았습니다.
페이로드 SHA256은 `910c33e9f75ce14d4ec10a28ceb5ecacf23e86ef7d16b257986084ecdb66f651`,
전체 원본 목록 SHA256은 `1180679ffd7ac3385759a806e8dc8fc8dd37f93cdf7e064c60f027be6b74e01b`입니다.
부트스트랩 해시는 목록에 있지만 직접 페이로드 시작으로 부트스트랩 시작을 증명하지는
않습니다. 독립 QA도 아래 별도 새 실행으로 통과했습니다.

최초 샌드박스 UBT 캐시 실패와 R1 수정 전 성공 빌드는 과거 시도로 유지하며,
현재 결과는 수정 후 재빌드에 근거합니다.

## 독립 게임플레이 QA와 최종 게이트

QA 실행 `fc4315d66ff74af9b5bfdf7c6ad06ec3`는 같은 실제 페이로드를 새로 시작해
69.515초 후 종료 코드 0으로 자연 종료했고 숫자 시나리오 12개를 독립 확인했습니다.
D3D12 패키지 게임 월드에서 저장한 맵과 배치 BP를 선택했고 마지막 각도 0·점유 0개였습니다.
QA 담당이 새 최종 화면을 직접 열어 닫힌 문·벽·표식과 읽을 수 있는 HUD를 확인했습니다.
해당 범위에서 사용자에게 보이는 결함은 보고되지 않았습니다.

검토한 스크린샷은 로컬에 보관하며 해시는 정리된 QA 결과에 남겼습니다.
문 소스 프로젝트·생성 에셋·실행 패키지·스크린샷·영상은 이번 공개에서 제외합니다.

기술 검증 목록의 원래 파일 48개와 페이로드 해시는 모두 일치했습니다. 다만 전체 폴더
목록이 같지는 않았습니다. 런타임이 만든 Saved 설정 파일 3개가 추가됐습니다. 최초
엄격한 목록 검사는 실행 전에 멈췄고, QA가 추가 파일을 보존·기록한 뒤 원래 패키지 내용의
동일성을 확인했습니다. SSL 인증서 저장소·GPU TSR 드라이버 대체 경고는 남았고 이 오프라인
시나리오에서 Error/Fatal/Ensure는 검출되지 않았습니다.

반전 샘플도 독립 확인했습니다. 12.2519초·점유 0개에서 49.6482도,
12.4042초·점유 1개에서 63.5549도, 13.6023초에 90도였습니다. 이 수치 관계는
자동 반전 검사를 뒷받침하지만 최종 정지 화면만으로 프레임별 시각적 연속성을 증명하지 않습니다.

총괄이 별도 QA 보고서를 기록하고 최신 게이트를 실행해 `exit_code: 0`, `ready: true`,
`state: complete`, `round: 2`, 사유 없음 결과를 받았습니다. Digest는 위의 수정된
2회차 값이며 에디터 소유권은 반납됐습니다. 아래 범위 한계를 유지한 샘플 절차 완료입니다.

## 에디터 결과와 복구한 시도

PIE 실행 `36f4decc51904200a16df1c76155977a`는 D3D12 게임 월드에서 반대쪽 접근과
연속적인 닫힘 반전을 포함해 **검사 12/12개**를 통과했습니다. 종료 상태는 문 각도 0,
점유 Pawn 0개였습니다. 에디터 담당이 PIE를 정지하고 작업 에디터를 정상 종료한 뒤
소유권을 반납했습니다. 독립 최종 QA와는 별도인 에디터 단계 결과입니다.

성공 전에 실패한 세 번의 시도도 보존했습니다. 쓰기 가능한 DDC 노드가 없어 메모리
캐시로 재시도했고, 변경 상태의 시작 Entry 맵이 로드를 막은 시도는 작업 소유 프로세스를
정지했습니다. 복제 맵이 아직 저장되지 않은 시도는 명시적 저장과 파일 확인으로
수정했습니다. 실패한 시도를 통과로 바꾸지 않았습니다. 임시 프로젝트에서 바꾼 설정은
기본 맵 키 2개뿐이며 전체 설정과 보안 토큰은 공개 증거에서 제외했습니다. 이번 PIE는
원점의 문을 사용했으므로 이동·스케일 배치, 중복 문 거부, 네이티브 대체 경로는
이 실행으로 검증됐다고 하지 않습니다.

## 검증 범위의 한계

로컬에 보관한 문 데모 영상은 이전 실행의
자료입니다. 현재 배치된 Blueprint 샘플·수정 소스·5개 전문 담당 실행을 보여주는
영상이 아닙니다. 이 작은 자동 샘플은 플레이어 조작·네트워크·저장·대규모 레벨이나
정의된 모든 TOML 역할의 실행을 검증하지 않습니다.

작업 구조는 [스튜디오 절차](../feature-loop.md), 참고한 접근 방식과의 비교는
[원본 스튜디오 비교](../upstream-studio-comparison.md)를 확인하세요.
